Real-Time Data Collection & Logging with Arduino

From reading a single sensor value, to continuously tracking it live, to sending it somewhere it survives. This handout covers every core concept, with worked examples and two interactive checks for understanding.

01Real-Time Data Collection

What "real-time" means here

Real-time data collection means your program keeps reading a sensor continuously, close to the moment each value happens, instead of reading once and stopping. On Arduino this means the sensor read has to repeat forever inside loop() — but it can't freeze anything else while it waits.

Why delay() breaks real-time behavior

delay(ms) pauses the entire program — no other code runs until it's done. That's fine for a single blinking LED, but the moment you need to also watch for a second sensor, update a display, or talk to WiFi, a blocking delay becomes a bug.

// BLOCKING — nothing else can happen during delay() void loop() { int value = analogRead(A0); Serial.println(value); delay(2000); // the whole board is frozen for 2 full seconds }

The non-blocking pattern: millis()

millis() returns the number of milliseconds since the board powered on — and it keeps counting in the background, no matter what else your code is doing. Comparing it against a saved "last time" value lets you time events without ever freezing the program.

// NON-BLOCKING — loop() keeps running every cycle unsigned long lastRead = 0; const long interval = 2000; void loop() { if (millis() - lastRead >= interval) { int value = analogRead(A0); Serial.println(value); lastRead = millis(); // reset the clock } // anything else written here still runs every single cycle }
Key idea: delay() stops time for your whole program. millis() just checks a clock that never stops — so your program stays responsive.

Storing live data: the rolling buffer

A single variable only remembers the most recent reading. To track a short history — for a running average, a trend, or a graph — collection uses a fixed-size array as a rolling buffer: new values overwrite the oldest ones, using the modulo operator (%) to wrap the index back to 0.

float readings[10]; // holds the last 10 values int idx = 0; readings[idx % 10] = newValue; // box 0..9, then wraps back to 0 idx++;

Turning the buffer into information

A loop over the buffer — the same traverse-and-accumulate pattern from earlier lessons — produces a rolling average, a running max, or any other live statistic:

float sum = 0; for (int i = 0; i < 10; i++) { sum += readings[i]; } float average = sum / 10;

02Real-Time Data Logging

Collection vs. logging — not the same job

Collection keeps data local and current. Logging sends that data somewhere it will survive after the board loses power or moves out of range — a cloud dashboard, an SD card, or a database — so it can be reviewed later or viewed remotely.

Logging to the cloud: ThingSpeak

ThingSpeak is a free IoT dashboard. Each "channel" accepts numeric values over WiFi and plots them automatically. The board needs a Write API Key to identify which channel it's sending to.

Rate limit: ThingSpeak's free tier accepts a new point no faster than once every 15 seconds. A sensor sampled every 2 seconds cannot log every reading — only a periodic summary of them.

Two timers, one shared array

Because sampling and transmission run at different speeds, a logging sketch needs two independent millis() timers inside the same loop() — one fast (collection), one slow (logging) — both reading from the same buffer.

#include <ESP8266WiFi.h> #include <ThingSpeak.h> WiFiClient client; unsigned long channelID = YOUR_CHANNEL_ID; const char* apiKey = "YOUR_WRITE_KEY"; float readings[10]; int idx = 0; unsigned long lastCollect = 0, lastLog = 0; const long collectInterval = 2000; // fast: local const long logInterval = 15000; // slow: cloud minimum void loop() { if (millis() - lastCollect >= collectInterval) { readings[idx % 10] = analogRead(A0) * (3.3/1023.0); idx++; lastCollect = millis(); } if (millis() - lastLog >= logInterval) { float sum = 0; for (int i=0; i<10; i++) sum += readings[i]; ThingSpeak.setField(1, sum / 10); ThingSpeak.writeFields(channelID, apiKey); lastLog = millis(); } }

Alternative: logging to an SD card

When WiFi isn't available or reliable, the same pattern logs to a local file instead — useful for field data collection with no network at all.

#include <SD.h> File logFile; if (millis() - lastLog >= logInterval) { logFile = SD.open("log.csv", FILE_WRITE); if (logFile) { logFile.print(millis()); logFile.print(","); logFile.println(average); logFile.close(); } lastLog = millis(); }

03Key Vocabulary

TermMeaning
Real-timeData is processed continuously, close to the moment it's generated.
Blocking codeCode (like delay()) that freezes the whole program until it finishes.
millis()Built-in timer counting milliseconds since the board started; never blocks.
Rolling bufferA fixed-size array where new values overwrite the oldest ones.
Sampling rateHow often a sensor is read (collection speed).
Transmission rateHow often collected data is actually sent/logged externally.
API keyA private code authorizing a device to send data to a specific channel.
